## [Unreleased]

### Added

- **Interactive Mermaid viewer and source inspector**: the centered Diagram gallery and `.mmd` / `.mermaid` File Preview now share an interactive Mermaid viewport with left-drag panning, normal mouse-wheel zoom around the cursor, toolbar zoom/reset controls, and pan/zoom state that survives live re-renders. A reusable CodeMirror-backed Mermaid source inspector opens from the gallery toolbar (`Edit` toggles to `Close`) and uses a responsive split layout: resizable side panel on wide panes, bottom drawer on narrow panes. Edits update the rendered diagram after a short debounce while preserving invalid source in the editor and surfacing Mermaid render errors without discarding drafts. Persisted plan diagrams gain explicit **Save** / **Revert** through a new `mermaid_update_diagram(workspace_cwd, slug, id, code)` Tauri command that updates `.agents/plans/<slug>/diagrams/<id>.mmd` while preserving manifest metadata; ad-hoc timeline diagrams can be edited and exported in-memory but do not show Save. `.mmd` / `.mermaid` file previews now route through the existing `EditorSession` buffer and conflict-guarded save/revert flow, keeping protected-folder and too-large-file rules intact. Verified with `cargo test -p blxcode agent::mermaid::store`, `cargo check -p blxcode-ui --target wasm32-unknown-unknown`, and `cargo fmt --check`.
- **BLXCode plugin packages and titlebar Run menu**: BLXCode now has a real, app-data-backed plugin package registry with built-in and GitHub-installed packages, categories, enable/disable/remove controls, and a new **Settings -> Plugins** tab. The first category is **runtime**, used by declarative plugin packages that contribute run-command detectors without executing plugin code. Built-in runtime plugins detect common project commands across Node/package managers (`npm`, `pnpm`, `bun`, `yarn`), Rust/Cargo, Go, CMake/Make, shell scripts (`sh`, `bash`, `ps1`, `bat`, `cmd`), and direct JavaScript/TypeScript entry points. A new titlebar **Run** menu appears after Worktree, scans the active local or SSH-remote workspace through enabled runtime plugins, groups run/dev/debug/test/build commands, and starts the selected command in a new visible terminal slot. GitHub install supports repository or package-directory URLs, optional Git ref/package directory inputs, staging validation for `blx-plugin.json`, install progress polling, and rollback on failed copy/registry writes. New Tauri commands: `plugins_list`, `plugins_install_from_github`, `plugins_install_progress`, `plugins_set_enabled`, `plugins_remove`, and `run_commands_discover`. User/developer docs and the implementation plan were updated. Verified with `cargo fmt --check`, `cargo test -p blxcode plugins::`, `cargo check -p blxcode`, and `cargo check --target wasm32-unknown-unknown`.
- **Git worktree workspaces**: BLXCode can now create, open, and manage Git worktrees as first-class workspaces for both local and Remote SSH repositories. Workspace entries persist worktree metadata, the Create Workspace flow supports branch/start-point/path worktree creation, and the left side of the custom titlebar now exposes an active-workspace-scoped **Worktree Management** menu for listing, opening, creating, refreshing, and safely removing worktrees. Backend commands resolve Git roots with `rev-parse`, parse `git worktree list --porcelain -z`, check for existing branch/path matches before creation, refuse dirty worktree removal, and run the same flow through the remote exec channel for SSH workspaces. Remote terminals now start in the selected worktree cwd. The BLXCode Agent receives active worktree scope in its system prompt and gains `harness.worktree_list` plus `harness.create_worktree_workspace`; creation requires a preview call, reports existing matches, asks the user to confirm, then creates or opens the worktree only after confirmation. User/developer docs and the implementation plan were updated. Verified with `cargo check`, `cargo check -p blxcode`, `cargo test -p blxcode git_worktree`, and `cargo test -p blxcode system_prompt`.

## [0.5.0] - 2026-06-04

### Added

- **HeartBeat runtime and Memory Indexer**: BLXCode now has an internal, plugin-ready HeartBeat orchestrator with global persisted settings, a clamped 10-minute to 24-hour interval, service enable/disable state, service status snapshots, manual `Run now`, and a new **Settings -> HeartBeat** tab. The first registered service is `memory_indexer`, which indexes all currently open workspaces asynchronously, keeps per-workspace runs from overlapping, skips already-running work, and marks a run stalled after three consecutive skips. Generated Memory notes are managed with frontmatter and written directly into the existing Memory categories (`rules`, `skills`, `plans`) for both workspace memory (`.agents/memory/...`) and global memory (`~/.blxcode/memory/...`), so the existing Memory graph and Graph3D clustering consume them without a separate `index` category. **Settings -> Memory** now shows Memory Indexer stats plus independent provider/model settings, and the left statusbar process area rotates active processes every three seconds, including Memory Indexer running or stalled state. New Tauri commands cover HeartBeat settings, service listing/toggles/run-now, open-workspace sync, and Memory Indexer settings/stats. Verified with `cargo check --manifest-path src-tauri/Cargo.toml`, `cargo check --target wasm32-unknown-unknown`, `cargo test --manifest-path src-tauri/Cargo.toml heartbeat::tests`, and `cargo test --manifest-path src-tauri/Cargo.toml memory::indexer::tests`.
- **Agent-authored Mermaid diagrams (foundation)**: the BLXCode Agent can now generate Mermaid diagrams as first-class objects via two new server tools — `mermaid_create` (one) and `mermaid_create_many` (several). When a `plan_slug` (and optional `task_id`) is supplied, each diagram is **persisted next to its plan** under `.agents/plans/<slug>/diagrams/<id>.mmd` with a `diagrams.json` manifest (id, title, kind, linked task, created), so plan/task diagrams travel in git and are removed when the plan folder is; without a `plan_slug` the diagram is treated as an ad-hoc, non-persisted chat diagram. The backend store (`src-tauri/src/agent/mermaid/`) derives unique kebab-case ids, guards against path traversal, and caps source size; the tools are wired into the `PlansWrite` tool group, dispatch, and mutating-edit classification, and the system prompt now documents the diagram capability plus the plan/task token-cost rule and architect/coordinator auto-generation behavior. A new **centered diagram gallery** center tab (`CenterTabKind::DiagramGallery`) renders a plan's diagram set as a horizontal thumbnail slider on top with the active diagram large below, reusing the existing vendored Mermaid renderer (`mermaid_glue`, `securityLevel: strict`) through a new shared `DiagramRender` component; each plan card in the Plans panel gains a button that opens the gallery for that plan. Diagrams export to **`.md`** (YAML front-matter + fenced `mermaid` block) and **`.pdf`** (the rendered SVG converted via `svg2pdf`, page orientation derived from the SVG dimensions) through a native **Save As** dialog (new `tauri-plugin-dialog` dependency + `dialog:allow-save` capability). New Tauri commands: `mermaid_list_diagrams`, `mermaid_create_diagram`, `mermaid_delete_diagram`, `mermaid_export_markdown`, `mermaid_export_pdf`. Plan tracked in `.agents/plans/agent-mermaid-diagrams/`. New i18n keys (`DiagramGalleryEmpty`, `DiagramExportMd`, `DiagramExportPdf`, `PlansOpenDiagrams`) with English values across all 14 locales (non-English pending translation). Verified with `cargo test -p blxcode` (321 passed, incl. 8 new mermaid unit tests) and `cargo check -p blxcode-ui --target wasm32-unknown-unknown`. Still in progress: ```mermaid fence auto-rendering in chat, and the workspace settings (render mode / auto-generate / default count) with the one-time token cost gate.
- **Agent-timeline inline Mermaid diagrams + diagram provenance + gallery stats/zoom**: `mermaid_create` / `mermaid_create_many` tool results now render **inline in the chat timeline** as diagram cards (title + kind chip, the rendered diagram, and per-diagram **Diagrams** / **Export .md** / **Export .pdf** actions) instead of raw JSON — completing the previously-pending "agent-timeline inline diagram card" item. Ad-hoc chat diagrams (no `plan_slug`) open in a new ephemeral gallery tab (`CenterTabKind::DiagramGroup`) that embeds the diagram set directly rather than loading from the store, while the existing plan gallery is unchanged. The centered gallery gains a **stats overlay** (bottom-left: position/count, diagram type, generation time, and the generating provider·model) and **zoom/center controls** (bottom-right: −/＋/reset buttons plus Ctrl/⌘-wheel), with a scrollable, scalable viewport. Each diagram now records **which provider/model generated it** (Option B): `DiagramMeta` (persisted), `DiagramOut`/`TimelineDiagram` (envelope/frontend), and `DiagramRecord` carry optional `provider`/`model`, stamped at creation time from the dispatch context for the **main agent and subagents** (threaded via `ToolExecOpts` → `run_create`/`store::create_diagram`); diagrams created before this was tracked simply omit the model line. The gallery reads provenance from the diagram data (no `agent_settings_get()` fallback). Stat labels (`Type`/`Generated`/`Model`) and zoom tooltips are currently English-hardcoded (i18n keys pending — see `/tmp/handoff-diagram-gallery-i18n.md`). Verified with `cargo test -p blxcode` (9 mermaid/plan tests, incl. new origin-stamping assertions) and `cargo check -p blxcode-ui --target wasm32-unknown-unknown`.
- **New BLXCode Agent text providers**: BLXCode Agent now supports Ollama, LM Studio, Hugging Face, Cloudflare Workers AI, Together AI, and Portkey alongside OpenRouter, Anthropic, and OpenAI. A central provider registry resolves OpenAI-compatible endpoints, auth modes, model discovery, reasoning support, OpenRouter extras, and curated fallback models. Ollama and LM Studio require no API key and expose a localized **Server URL** field in Settings -> BLXCode Agent for LAN or remote `/v1` servers; Cloudflare stores its Account ID as a non-secret setting while tokens and other cloud keys live in Settings -> API Keys with `BLX_*` environment fallbacks. Main chat, one-shot utilities, prompt enhancement, AI plans/tasks, AI commit messages, compaction, MCP tools, and subagents use the generalized compatible loop. Image and Voice provider lists remain separate/text-only in this release.
- **Workspace Multi-Kanban for plans**: every workspace now gets a pinned center-tab `0` Kanban view backed by `.agents/plans/` and persistent layout metadata under `.agents/kanban/index.json`, while the Terminal tab remains the active default view. The Kanban groups plans by the same derived states as the Plans side panel and nests task-state lanes for each plan, with quick task creation, inline rename/delete, drag-to-status updates, search, refresh, layout import/export, titlebar Navigate shortcut, notification targeting, i18n, token-only styling, async Tauri commands, and BLXCode Agent tool support. Kanban and the right-side Plans panel now share a Workbench plans revision signal, so create/write/rename/delete actions in the Plans panel and create/update/delete/drag actions in Kanban invalidate both views and keep their plan/task state synchronized.
- **Interactive Kanban drag and drop**: the Workspace Kanban board now supports moving whole plans between derived status sections and reordering plans within the board through dedicated dashed drop zones and a cursor-following drag preview that matches the existing terminal/context DnD styling. Plan drops write back to the plan's canonical Markdown task lines using a minimal status-change policy, while subtask drops are constrained to their parent plan and can change both status lane and Markdown order. New `kanban_plan_move` and `kanban_task_move` commands keep layout metadata separate from plan content, update mirrored runtime tasks where available, and bump the shared Plans revision so the right-side Plans panel reloads in sync.
- **Welcome-screen "Create Workspace" action**: the empty/welcome screen now leads with a prominent, highlighted **Create Workspace** call-to-action (folder-plus icon + hint) above the Agent/Memory/Browser/Kanban destinations row. It is backed by a real, rebindable shortcut — a new `ShortcutAction::CreateWorkspace` (default **Ctrl+B then C**) that appears in **Settings → Shortcuts** like every other binding, dispatches through the shared harness action path to open the inline Create-Workspace configurator, and is fully internationalized (label + hint across all 14 locales). The welcome destination cards and utility links now also **hide their keybinding hints when the workspace panel is narrow** (e.g. split view), via a container query, so the `kbd` chips no longer overlap or crowd the labels. Token-only styling.
- **MCP (Model Context Protocol) server support**: BLXCode can now register MCP servers in a new **Settings → MCP** tab and expose them to both the in-app agent and the bundled terminal CLI agents. A central registry (`{app_data_dir}/mcp/servers.json`) stores each server with a **stdio** (command/args/env) or **HTTP** (url/headers) transport, an individual **on/off switch**, and add/edit/remove plus a per-server **connection test** (`initialize` + `tools/list`, with a live tool count). For the **in-app agent**, each enabled server is connected at session start through a minimal built-in JSON-RPC MCP client; its tools are discovered and injected into the Anthropic and OpenRouter/OpenAI tool loops as `mcp.<server>.<tool>` (name encodings handled across both providers), and `mcp.*` calls are routed back to the right client in tool dispatch. For the **terminal CLIs** (`claude`, `codex`, `gemini`, `opencode`, `cursor`), the enabled servers are translated into each CLI's native, project-scoped config and written into the workspace root on launch (`.mcp.json`, `.codex/config.toml`, `.gemini/settings.json`, `opencode.json`, `.cursor/mcp.json`) — merge-safe, preserving foreign entries and tracking BLXCode-managed keys in a `.blxcode/mcp-managed.json` sidecar; remote SSH workspaces are skipped. The available tool set is fixed at session start, so the MCP pane shows a **mandatory session-reset reminder** (with a one-click "reset session" button) and raises a **reload-required hint** whenever a server is added, edited, removed, enabled, or disabled — enable/disable applies to the in-app agent after a session reset and to terminal CLIs after an app reload. The system prompt now documents MCP tools, and a new embedded core skill, `mcp`, explains recognition, the enable/reset lifecycle, the terminal-CLI export, and the rule to treat MCP output as untrusted data. Fully internationalized across all 14 locales (27 new keys, machine-translated via the locale render script). Verified with `cargo test --workspace` (incl. 14 new MCP unit tests), `cargo check -p blxcode-ui --target wasm32-unknown-unknown`, and `scripts/lint_theme_tokens.sh`.
- **Per-terminal CLI-agent model and effort selection**: Create Workspace now lets each fleet agent row choose both the CLI-agent model and, where the agent supports it, a reasoning/effort level. Selections are persisted on workspaces and presets, kept aligned when terminal slots are reordered, swapped, transferred, added, or removed, and applied when launching/resuming terminal agents. Launch profiles now map supported effort values into the correct CLI mechanism: Claude via `CLAUDE_CODE_EFFORT_LEVEL`, Codex via `-c model_reasoning_effort=...`, and Gemini/OpenCode/Cursor as model-only until their CLIs expose confirmed launch-time effort flags. User and developer docs now document the model/effort behavior.
- **Terminal view modes: Grid, Canvas, and Swarm**: the live Terminals tab can now switch between the standard grid, a freeform **Canvas** where terminal slots become draggable/resizable nodes with `stdin` / `stdout` routing ports, and a **Swarm** graph that visualizes the BLXCode Agent control hub plus terminal-agent nodes. Canvas layouts, routing edges, transfer mode, and Swarm node positions are persisted with the workspace snapshot.
- **Terminal CLI-agent control and prompt enhancement**: BLXCode Agent can now drive interactive terminal agents end to end through the harness. New terminal-control tools support listing/targeting terminal slots, sending raw keys or attached BLXCode context, reading recent output, waiting for new/settled output with sequence ids, and interrupting stuck sessions with Ctrl+C. CLI-agent launch/resume profiles for `claude`, `codex`, `gemini`, `opencode`, and `cursor` are centralized so UI launch commands, docs, and agent guidance stay in sync. A new embedded core skill, `prompt-generating`, teaches the agent how to formulate scoped prompts for BLXCode chat, terminal CLI agents, subagents, or user-facing responses, and the system prompt now requires using that skill before substantive CLI-agent handoffs. The composer also adds a per-workspace **Enhance prompt before send** toggle that rewrites the draft through an isolated one-shot provider call before submitting it as the actual user turn, without mutating chat history, tools, memory, plans, or timeline state.
- **Agent timeline refactor: grouped tool calls, changed-files card, and modern composer**: the chat timeline now renders consecutive tool activity as slim grouped status rows for both the main agent and subagent cards, preserving per-tool icons, argument summaries, status indicators, expandable details, metrics, path aggregation, and `×N` counts through a reusable `tool_group` component. Model turns that mutate files can now end with a **Changed files** summary card built from the existing `git_status_changes` command: it totals additions/deletions, renders a collapsible directory tree with per-file stats, opens file diffs on click, and links to the existing diff view without adding any backend protocol fields. The old mode toolbar plus single-line input was replaced by a modern auto-growing composer textarea with a footer model picker, Plan/Build/access mode popover mapped onto the existing `AgentChatMode` values, thinking-level selector, busy-safe controls, and send/stop orb. New components live in dedicated `agent_panel/{tool_group,changed_files_card,composer}` folders with token-only CSS; the new strings are fully internationalized across all 13 locales. Verification covered `cargo check -p blxcode-ui --target wasm32-unknown-unknown`, `cargo test --workspace`, and `scripts/lint_theme_tokens.sh`.
- **Roundings & Font controls** (Settings → Appearance): two new theme-independent appearance knobs sit above the theme grid. **Roundings** is a global corner-radius scale — *Sharp / Default / Rounded / Extra* — driven by a single `--radius-scale` multiplier over a new semantic token set (`--radius-{xs,sm,md,lg,xl}`); pills and circles (`--radius-pill`/`--radius-circle`) intentionally do not scale. 247 previously hardcoded `border-radius` declarations across `styles.css` and component CSS were migrated to these tokens, so the whole workbench re-rounds instantly. **Font** is a curated monospace picker (JetBrains Mono bundled, plus Cascadia Code, Fira Code, SF Mono, Menlo, Consolas and System Monospace as system-dependent options, each rendered in its own typeface) that overrides the central `--font-mono` token; it is also wired into the xterm terminals, which now read their `fontFamily` from `--font-mono` and re-measure/re-fit (with a PTY resize) when the font changes. Both settings are app-wide, persisted in `localStorage`, and applied as inline custom properties on `<html>` through `ThemeService` (dispatching `blxcode-theme-changed` so the terminal/graph bridges re-read CSS). They are orthogonal to the selected theme. 10 new i18n keys across all 13 locales.

The previous GitHub-blue default lives on unchanged as **BLXCode Legacy** / **BLXCode Legacy Light** (new ids `blxcode-legacy-dark` / `blxcode-legacy-light`), so anyone who preferred the old look can switch back. `blxcode-dark` stays the default id, so existing users land on the new design automatically. The catalog grows from 30 to 32 themes; both new and legacy themes ship the complete token set (surfaces, borders, text scale, accent + accent-cool, six overlay levels, terminal, agent brand colors, six git-graph lanes, and the `color-mix`-based follow-up tokens). Names and descriptions added to all 13 locales.

- **Push-to-Talk speech-to-text** (**Settings → Voice → Push-to-Talk**): hold a key, speak, and the transcript is routed to a target of your choice — **local-first** via a warm `whisper.cpp` model, with an optional **cloud** mode that reuses the existing OpenAI/OpenRouter STT providers (AWS Polly is correctly *excluded* from STT — it is text-to-speech only). The hotkey is configured like every other shortcut under **Settings → Shortcuts → Push-to-Talk** (new `ShortcutAction::PushToTalk`, default **Ctrl+Shift+Space**, full rebind/reset/conflict UI); it is a *hold* key handled by a dedicated window-level runtime (`workbench/ptt_runtime`) and is intentionally excluded from the single-press chord dispatch. **Targets**: agent composer (optional auto-submit), active terminal (auto-submit appends Enter via `pty_write`), active text input, or clipboard — with a **target mode** that either follows the current focus or is *remembered at PTT start* so a focus change mid-utterance is ignored. **Live partial transcript** is on by default (produced by periodically re-decoding the captured audio, since `whisper.cpp` has no native streaming) and can be turned off to save CPU; it shows in a floating, token-styled indicator. A **collision state machine** (`VoiceRuntimeState`) keeps push-to-talk from clashing with the existing agent voice orb or TTS playback — while TTS is playing it can **Stop**, **Pause**, or **Block** recording (default Block) to avoid a feedback loop, and a second microphone session is refused. Backend lives under `src-tauri/src/voice/{ptt,models,stt}` with an in-memory PCM capture path (no temp WAV), the model held warm in Tauri state and inference run off the async runtime; commands `ptt_start/partial/finalize/cancel`, `voice_tts_playing`, `voice_agent_input_active`. The local engine is compiled behind the `local-whisper` cargo feature (pulls `whisper-rs` + a native toolchain); default builds support cloud PTT only and report a clear error if a local model is used. **52 new i18n keys**, German hand-translated and the other 11 locales filled via the render script. User and developer docs updated (`docs/{user,developer}/voice.md`).
- **Whisper model manager** (in the Push-to-Talk section, local mode): a filterable list of downloadable `whisper.cpp` models (the official GGML weights from `ggerganov/whisper.cpp` on Hugging Face) with **filter tabs** (All / Standard / Quantized / Turbo / Large), per-model **size**, language (multilingual / EN-only) and **Speed / Accuracy** dot ratings, and a **"best for"** hint. Downloads show a **live progress bar with transfer speed (MB/s)** driven by throttled Tauri events (`whisper_download_progress/done/error`) and are **resumable** — an interrupted or paused transfer keeps its `.part` and continues via an HTTP `Range` request (falling back to a full download if the server ignores it), with a **Resume** / **Discard** choice; finished files are sha256-verified and atomically renamed into place. Installed models show **Installed** state with **Use** (select as the active model, stored in `PttSettings.local_model_path`) and **Delete**. Models are stored under `<app-data>/voice/models/<id>.bin`; a free-form custom path remains available for power users. The download runs as a background task and never blocks the IPC handler.
- **AI-generated plans & tasks** (Plans panel): two new header buttons — **AI Plan** (LuSparkles) and **AI Tasks** (LuListPlus) — open a dialog where a short prompt is turned into a full Markdown plan by the agent tab's configured provider/model. Generation reuses the existing one-shot, non-streaming path (`oneshot::complete_text`) that already backs AI commit messages — no second LLM stack, no chat conversation, no events. A new backend command `plan_generate_ai { prompt, with_tasks }` (`src-tauri/src/agent/plan_ai.rs`) drives a Skill-conformant system prompt so the output always matches the built-in plan format (`# Title` + prose sections + a `## Tasks` section using the exact `- [ ] \`task-id\` - Title` line syntax). Post-processing strips any wrapping code fence, extracts the title (falling back to the prompt), and guarantees a `## Tasks` heading exists so `plan_load` never runs empty. The dialog shows a **shimmer loading animation** over the prompt box while generating, then a **scrollable Markdown preview** with **Save** / **Regenerate** / **Cancel**; a **toggle** decides whether tasks are created alongside the plan (forced on and disabled in *AI Tasks* mode). Saving persists through the existing tools only — `plan_create` writes the file and, when tasks are requested, `plan_load` syncs the `## Tasks` section into the task manager — so no new write path to `.agents/plans` is introduced. Empty prompt and missing-API-key cases surface the same friendly errors as AI commit. New component lives in its own subfolder with its own token-only CSS (shimmer keyframes + `prefers-reduced-motion` fallback). 14 new i18n keys, fully internationalized across all 13 locales.
- **Configurable tool-loop limit** (**Settings → Agent**): the per-turn ceiling on tool-call rounds — previously the hard-coded `MAX_ROUNDS = 36` that produced *"Tool-Loop-Limit erreicht (36 Runden)"* when a long investigation ran out of rounds — is now a user setting. A number field (range 1–500, default 36) next to *Thinking level* drives both the OpenAI-compatible (OpenRouter/OpenAI) and Anthropic coordinator loops; the value is clamped on save and again at the call site so a hand-edited config can never produce a zero-round or runaway loop. Fully internationalized across all 13 locales.
- **3D Drobo Agent orb with 2D fallback toggle** (**Settings → Agent**): the Agent tab's voice orb can now render the bundled `public/assets/Drobo.glb` as an interactive Three.js model that smoothly follows the cursor, recolors itself from active theme tokens, reacts to recording/transcribing states, and falls back to the original flat `B` logo when WebGL/model loading is unavailable. A new persisted **Agent orb** switch in BLXCode Agent settings lets users choose between the default **3D Drobo** mode and the lighter **2D logo** mode; saving the setting updates the open Agent tab without restarting.
- **Context-window usage meter**: the Agent session stats panel now shows how much of the model's context window the current conversation occupies as `used / max · NN%` with a thin progress bar that shifts color past 70% (warning) and 85% (danger). The max size is resolved from the provider's own model metadata — OpenRouter's `context_length` is cached per model, and a static fallback table (`agent/context_window.rs`) covers the direct providers (Claude 200K, GPT-5 400K, Gemini 1M, GPT-4.1 1M, …); unknown models degrade to a plain token count with no percentage rather than inventing a denominator. Occupancy tracks the **newest main-agent round's** prompt size (true window occupancy), not the cumulative token sum used for cost, and subagent rounds are excluded. Fully internationalized across all 13 locales.
- **Agent session stats panel**: the Agent hero now uses the left grid column for a compact live stats panel while the Drobo orb remains on the right with wider spacing and no duplicate text status below it. The panel is intentionally unframed — no card chrome and no stats tooltips — and derives all values client-side from the existing timeline, usage aggregate, context-window signal, model label, and busy state: provider/model with a single state chip that follows open Thinking blocks before falling back to Running/Standby, local session start time, context-window occupancy with a mini meter, combined `User: x / Model: y` turns, total tool calls only, active-subagent count and names, and accumulated session cost. - **Terminal drag & drop now works on Windows**: dragging a terminal slot let you grab it (and showed the floating preview) but never produced a drop — the slot could not be moved or dropped onto another slot. - **Plan Manager**: durable Markdown plans under `<workspace>/.agents/plans/`, with `PLANS.md` as a protected index seeded on workspace bootstrap. Each plan can declare a canonical `## Tasks` (or `## Todos`) section using the syntax `- [ ] \`task-id\` - title` where the marker is one of `[ ] [>] [!] [x] [-]` (pending/in-progress/blocked/completed/cancelled).
- **Plans tab** in the right panel (between Browser and Memory): list with per-plan task summary, Markdown editor with debounced auto-save, preview toggle, create/rename/delete, and a "Load into BLXCode Agent" action that syncs plan tasks into the task manager and attaches the plan to shared context. On workspace activation, the panel auto-opens the last-active plan via the persisted `activePlanPath`.
- **Plan-linked tasks**: `TaskRecord` gains optional `planPath` / `planTaskId`; `TaskSnapshot` gains `activePlanPath`. `plan_load` replaces only tasks where `planPath == path` and leaves free tasks untouched. `task_update` on plan-linked tasks writes status changes back into the plan Markdown automatically. The Agent panel's task list groups plan-linked tasks by plan first, then renders a separate **Free Tasks** group.
- **Agent tools**: `plan_list`, `plan_read`, `plan_create`, `plan_write`, `plan_delete`, `plan_rename`, `plan_load`, `plan_sync_from_tasks` (server-side), and `plan_context_list`, `plan_context_attach`, `plan_context_detach` (client-side).
- **Tauri commands**: `plan_list`, `plan_read`, `plan_create`, `plan_write`, `plan_delete`, `plan_rename`, `plan_load`, `plan_sync_from_tasks` under `src-tauri/src/plans.rs`.
- **Shared context kinds**: `AgentContextKind::{PlanIndex, PlanFile, PlanTaskGroup}` (mirrored in `src/agent_wire.rs`). `render_context_prompt` renders attached plans separately from memory, citing per-plan task counts.
- **Terminal handoff**: `harness.send_agent_context.includeKinds` accepts `"memory" | "plans" | "tasks" | "images"` (default: all four). Renderer adds a new `## Attached plans / tasks` section with per-plan status counts, the active/in-progress task title, and a compact task list. The handoff renderer is primed by a per-workspace task-snapshot cache populated by the Plans/Agent panels on workspace activation so the synchronous renderer surfaces restored plan state immediately after a reload.
- **System prompt — mandatory Turn checklist**: explicit ordered steps at the top of the prompt that the agent must run every turn — (1) `rules_list` + `rules_read` on relevant active rules as a binding first step, (2) `skills_list` + `skills_read` on matching skills when the task warrants, (3) **Resume check** that recognises continuation directives in English (*continue, keep going, resume, proceed*) and German (*weiter, fortsetzen, weitermachen, mach weiter*) and resumes from `task_list` / `activePlanPath`, (4) memory/project context as needed, (5) execute. Trivial conversational turns may skip steps 1–2.
- **Workspace plans system-prompt section**: explains plan tooling, `## Tasks` line syntax, the `task_*` vs. `plan_*` separation, automatic status write-back, and that plan files and the task store survive workspace reload / harness restart / OS exit — so `plan_list` + `task_list` reconstruct in-flight work authoritatively after a restart.
- **i18n**: `TabPlans` plus Plans-panel keys (`PlansEmptyTitle`, `PlansEmptyLead`, `PlansNewPlan`, `PlansNewPlanPh`, `PlansRename`, `PlansDelete`, `PlansSelectPlan`, `PlansEdit`, `PlansPreview`, `PlansLoadIntoAgent`, `PlansLoaded`, `PlansRefresh`, `PlansTaskSummary`, `PlansTaskStatTotal`, `PlansTaskStatPending`, `PlansTaskStatInProgress`, `PlansTaskStatBlocked`, `PlansTaskStatCompleted`, `PlansTaskStatCancelled`, `PlansProtectedIndex`) added to all 14 locales; `TabPlans` and `de_de` task-stat labels are translated, other locales fall back to English for the stat keys.
- **Tests**: 11 new plan tests covering CRUD round-trip, `PLANS.md` protection, path-traversal sandboxing, parser status markers + `## Todos` alias, `plan_load` replace-only-plan-tasks semantics, `task_update` status write-back to plan Markdown, `plan_sync_from_tasks` round-trip preserving non-Task sections. New handoff-renderer tests for the plans/tasks section. New system-prompt tests verifying the mandatory Turn checklist, all continuation keywords, and the persistence guarantee.
- **Sidebar layout — bottom panel**: Project Files and Git graph share a single `.workbench-sidebar__panels` block (default **50%** of sidebar height, not the full area below Workspaces). A horizontal drag handle between the workspace list and this block resizes the combined panel; the existing handle inside the block still splits Explorer vs. graph (`blxcode_sidebar_panels_height_pct_v1` / `blxcode_sidebar_explorer_height_pct_v1` in `localStorage`).
- **Sidebar width**: drag handle on the right edge of the sidebar (like the right panel splitter) resizes width in pixels; default **260px** (was `clamp(216px, 22vw, 280px)`). Persisted as `blxcode_sidebar_width_px_v1` and on `WorkbenchSnapshot.sidebar_width_px`.
- **Project Explorer — hidden files**: toolbar eye toggle (`LuEye` / `LuEyeOff`) shows or hides dot-prefixed entries client-side; preference stored as `blxcode_sidebar_explorer_show_hidden_v1` (default off).
- **Project Explorer — tree navigation**: clicking a folder row (name/icon area) expands or collapses the tree; the chevron still works and does not double-toggle.
- i18n: `SbExplorerShowHidden`, `SbExplorerHideHidden`, `SbExplorerResizeAria`, `SbPanelsResizeAria`, `SbWidthSplitterAria` — added to all 14 locales (`de_de`, `fr_fr`, `es_es` translated for the new strings).

## [0.1.10] - 2026-05-20

### Added

- Terminal agent context handoff: new BLXCode Agent client tool `harness.send_agent_context { slotId? | agentSlug?, instruction?, includeKinds?, submit? }` that hands off the active workspace's attached Memory/Learnings/Images to a live `claude` / `codex` / `gemini` / `opencode` / `cursor` CLI session in the workbench terminal grid. Renders a terminal-safe Markdown block (workspace root, attached items, image paths, optional instruction), writes it through the existing PTY path, and submits by default. Image bytes are exported to disk and cited by path — base64 is never written into the prompt.
- Image export pipeline for context handoff: new Tauri command `agent_export_context_images` writes selected images to `<workspace>/.blxcode/agent-context/images/` with sanitized filenames and a JSON manifest sidecar; collision-safe (`-2`, `-3` suffix) and idempotent across retries.
- Terminal PTY env vars `BLX_AGENT_CONTEXT_DIR` and `BLX_AGENT_CONTEXT_MANIFEST` so hooks and the spawned CLI agent can discover the workspace handoff directory and manifest path. Hooks remain advisory — the explicit toolcall is the only transport.
- Terminal titlebar **handoff dropdown** on every workspace terminal cell: opens a menu listing every live terminal in the workspace (so context can be forwarded to any peer slot), a separator, and a "Send to BLXCode agent context" entry that attaches the workspace's Memory category to the BLXCode Agent context (idempotent upsert). Button icon briefly flips to a check or alert and the border tints green / red as visual feedback (~2.8 s).
- Memory **Graph preview** handoff button: the note preview popover gains a terminal-share icon (next to "Open in Files" / "Close") that opens the same dropdown. Picking a terminal sends ONLY this note as a one-shot `memory_note` / `learning_note` context item; the "Send to BLXCode agent context" entry attaches the previewed note to the BLXCode Agent context.
- Shared frontend module `agent_context_handoff` containing the Markdown renderer (`render_agent_context_block`), the `WorkspaceTerminalTarget` listing, the async `perform_handoff` helper, and the reusable Leptos components `HandoffMenu` + `TerminalSlotHandoffButton`. The renderer is the single source of truth for the prompt shape and is fully unit-tested (empty / memory-only / image-only / mixed-with-instruction / long-path collapsing).
- `pty_sessions_signal()` accessor on `WorkbenchService` so UI components can react to live PTY session registration (button enables the instant the cell registers; no stale-disabled states).
- i18n keys for the new UI: `MemGraphSendToTerminal`, `HandoffSendContext`, `HandoffPickTerminal`, `HandoffNoTerminals`, `HandoffOkSent`, `HandoffFailed`, `HandoffToAgentContext` — German strings translated, all 12 other locales stubbed with the English fallback.
- Agent Panel image context: attach PNG, JPEG, WebP, or GIF images to the BLXCode Agent via OS/browser drag-and-drop or paste.
- Agent Panel drop-zone feedback: dragging images over the Agent chat highlights the pane with a dashed border and helper text; unsupported drops show a rejection hint.
- Agent Context image rows: attached images show Pending/Read status, remove controls, manual “use again” reactivation, and a preview dialog with close/remove actions.
- BLXCode Agent multimodal provider integration: pending images are sent once through OpenAI/OpenRouter and Anthropic vision payloads, then marked read via an `ImageContextConsumed` event.
- BLXCode Agent image context client tools: `image_context_list` and `image_context_detach`.
- Native image file validation command for dropped files, including MIME detection and per-image size limits.
- Right panel **Rules** tab: cards for every `.agents/rules/rule-*.md` with title, summary, enabled/disabled pill, toggle, read, and remove controls; refresh button auto-loads on tab activation and workspace switch.
- Right panel **Skills** tab: cards for every `.agents/skills/<name>/SKILL.md` with source badge (`git` / `npm` / `local` / `agent`), `SKILL.md missing` warn marker, toggle/remove controls, and an **Install skill** dialog.
- Skill install dialog: segmented `Git` / `npm` / `Local` source picker with name + per-source fields; submits through the new `skills_install` Tauri command, shows progress and per-attempt error inline.
- Tauri command surface for skills & rules: `rules_list`, `rules_read`, `rules_write`, `rules_set_enabled`, `rules_remove`, `skills_list`, `skills_read`, `skills_write`, `skills_set_enabled`, `skills_remove`, `skills_install`, and `skills_rules_bootstrap`.
- On-disk manifests `.agents/rules/index.json` and `.agents/skills/index.json` tracking enabled state and (for skills) source provenance; atomic writes via tmp + rename, self-heal removes orphan entries at read time.
- First-touch bootstrap: when a workspace is opened, the harness auto-creates `.agents/{rules,skills}/` and seeds each `index.json` from the on-disk content (every existing rule and skill folder enters as `enabled: true`, skills with `source.kind = "local"`); manually disabled entries survive subsequent bootstraps.
- Skill install pipeline: `git clone --depth=1 --single-branch` for `git`, `npm pack` + `tar -xzf --strip-components=1` for `npm`, recursive copy for `local`; every install stages into `.install.<name>.tmp/`, validates that `SKILL.md` is present at the top level, and rolls the staging dir back on any failure.
- BLXCode Agent server tools mirroring the Tauri commands: `rules_list`, `rules_read`, `rules_write`, `rules_set_enabled`, `rules_remove`, `skills_list`, `skills_read`, `skills_write`, `skills_set_enabled`, `skills_remove`, and `skills_install { name, source: { kind, url?, ref?, package?, version?, path? } }`.
- System-prompt section for workspace skills & rules: active rules are declared **binding and non-negotiable** and outrank skill guidance; disabled entries must be treated as if they did not exist; install/remove require explicit user requests; `index.json` is harness-managed, not hand-edited.
- i18n: new keys `TabRules`, `TabSkills`, `SrRulesEmpty`, `SrSkillsEmpty`, `SrEnable`, `SrDisable`, `SrInstallSkill`, install-dialog labels and placeholders, status pills (`enabled`/`disabled`), `SrMissingSkillMd`, and `SrNoWorkspace` — added to all 14 shipped locales.
